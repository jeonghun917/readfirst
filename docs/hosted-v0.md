# readfirst 유료판(서버) 설계 v0

## 1. 나누는 선

| | 무료 (공개, 고객 쪽에서 돎) | 유료 (우리 서버에서만 돎) |
|---|---|---|
| 무엇 | `readfirst` 명령어, GitHub Action | GitHub 앱 "readfirst" |
| 지도 | 폴더별 초안(`init`), 사람이나 고객의 AI가 채움 | **AI가 지도를 채워 PR로 올림**(`fill`) |
| PR 댓글 | Action을 넣으면 됨 | 앱을 설치만 하면 됨(설정 파일 없음) |
| 지도 유지 | `check`가 빨간불 | **PR이 합쳐질 때 새 위험·규칙을 AI가 제안** |
| 여러 저장소 | 없음 | 회사 공통 규칙, 한 화면에서 보기(나중) |

무료판 코드는 공개돼도 괜찮게 짠다. 돈 받는 판단(어떤 위험을 적을지, 무엇을 규칙으로 볼지)은 서버의 프롬프트와 절차에만 있다.

## 2. 첫 유료 기능: 지도 채우기(fill)

1. 고객이 GitHub 앱을 저장소에 설치한다. 권한은 코드 읽기, PR 쓰기, 이슈 댓글 쓰기뿐이다.
2. 설치 직후, 또는 PR에 `/readfirst fill` 댓글을 달면 우리 서버가 일을 시작한다.
3. 서버는 그 저장소를 임시 폴더에 받는다(설치 토큰 사용). 무료판과 같은 `init`으로 묶음과 import를 계산한다. LLM 없이 0.1초면 된다.
4. Claude가 묶음마다 파일을 골라 읽고 다음을 채운다. 쓸 수 있는 도구는 "파일 읽기, 목록 보기, git 기록 보기" 세 가지뿐이다(읽기 전용).
   - 묶음 설명
   - 돌릴 검사(`package.json` 스크립트 등 실제로 있는 명령만)
   - 위험(구체적인 것만, 근거 파일 줄을 같이 적음)
   - 규칙(코드, 문서, 테스트에서 근거를 댈 수 있는 것만)
5. 서버가 `readfirst check`를 통과할 때까지 고친 뒤, `.readfirst/map.json`을 PR로 올린다. 위험과 규칙마다 근거를 PR 본문에 적는다.
6. 받은 코드와 임시 폴더는 작업이 끝나면 지운다. 코드를 저장하지 않는다. 남기는 것은 작업 기록(저장소 이름, 시각, 토큰 수, 비용)뿐이다.

**비용(Claude Opus 5.5 기준: 입력 100만 토큰당 $4, 출력 $20)**
- 파일 500개쯤인 저장소라면 입력 약 30만, 출력 약 2만 토큰이 든다. 1회에 약 $1.6이다.
- 급하지 않은 작업을 묶음 처리(Batch)로 돌리면 절반이고, 같은 앞부분을 다시 보낼 때는 캐시로 더 싸진다.
- 월 구독료($15~29)에 비해 작다. 큰 저장소는 상한을 둔다(예: 파일 3,000개 넘으면 묶음 일부만).

## 3. 두 번째 유료 기능: 지도 유지

- PR이 합쳐지면 바뀐 파일과 그 PR의 리뷰 댓글을 보고, "새로 적을 만한 위험·규칙"을 Claude가 1~3개 제안한다.
- 제안은 작은 PR이나 댓글로 올린다. 자동으로 합치지 않는다.
- 지도가 코드에 뒤처지는 것(`check` 빨간불)을 고치는 PR도 같이 올린다.

## 4. 만드는 곳

- 서버: Vercel 함수(웹훅 받기) + 작업 실행기. 저장소를 받아 AI를 오래 돌려야 하므로, 실행기는 함수 시간 제한이 없는 곳에 둔다.
  - 선택지 A: Claude Managed Agents. Anthropic이 실행 공간을 대신 띄워 준다. 관리할 서버가 없다.
  - 선택지 B: 작은 컨테이너(AWS 등)를 직접 운영한다.
  - 처음에는 A를 추천한다.
- 기록: Neon(Postgres)에 설치, 작업, 결제 상태를 저장한다. 코드는 저장하지 않는다.
- 결제: Stripe 구독. 저장소 수나 회사 단위로 받는다.
- 웰스미어, 대시보드와는 코드도 DB도 따로 둔다.

## 5. 가격 (처음 안)

| | 가격 | 내용 |
|---|---|---|
| Free | $0 | 명령어, Action, 공개 저장소에서 fill 1회 |
| Pro | 저장소당 월 $15 | fill 무제한(월 상한 있음), 지도 유지 제안, 앱 댓글 |
| Team | 월 $99부터 | 저장소 10개, 회사 공통 규칙, 한 화면 보기 |

## 6. 순서

1. **H1:** GitHub 앱 등록, 웹훅 받기, `fill` 1회 실행부터 PR 올리기까지. 우리 저장소(readfirst, 벨룸)로 시험한다.
2. **H2:** 결제(Stripe)와 사용량 상한을 붙이고, 소개 페이지에 "설치" 버튼을 단다.
3. **H3:** 지도 유지 제안을 만든다.
4. **H4:** 회사 공통 규칙과 한 화면 보기를 만든다.

## 7. 정할 것

- **D1** 실행기: A(Managed Agents)로 할지, B(직접 운영)로 할지.
- **D2** 모델: Claude Opus 5.5가 기본이다. 비용을 더 줄이려면 Sonnet 5.5(입력 $2, 출력 $10)로 갈 수 있다. 품질을 보고 정한다.
- **D3** 가격: 위 표 그대로 할지.
- **D4** 무료 부분의 라이선스: MIT로 할지, 상업적 복제를 막는 BSL로 할지.
- **D5** Anthropic API 키와 결제 계정: readfirst 전용으로 새로 만들지.
